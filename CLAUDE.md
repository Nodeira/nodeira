# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

Nodeira is an Obsidian-like, AI-enhanced note-taking application. Key differentiator: AI can read/write notes via CLI skill tool calls, making it usable as an AI "mind" for storing application state during software development workflows. Plugins will allow storing data in formats optimized for token efficiency and AI consumption.

## Tech Stack

- **Monorepo:** Turborepo + pnpm workspaces
- **Backend (`apps/api`):** NestJS 10, Prisma ORM, PostgreSQL, Hocuspocus (Yjs WebSocket server)
- **Frontend (`apps/web`):** React 19, Vite 6, TanStack Router (file-based), TanStack Query v5, Mantine v9, Jotai, TipTap + Yjs
- **Docs (`apps/docs`):** Docusaurus 3
- **Desktop (planned):** Electron
- **Mobile (planned):** React Native
- **Shared:** `packages/shared-types` (Note, NoteLink, NoteMetadata interfaces)

## Commands

```bash
pnpm install                          # install all workspace deps
pnpm run dev                          # start all dev servers via Turborepo (web :5173, server :3001, docs :3002)
pnpm run build                        # build all packages
pnpm run typecheck                    # type-check all packages
pnpm run test                         # run all tests
pnpm exec turbo run dev --filter=@nodeira/web     # run only web dev server
pnpm exec turbo run dev --filter=@nodeira/api  # run only server dev server
pnpm exec turbo run dev --filter=@nodeira/docs    # run only docs dev server
```

**First-time setup** (PostgreSQL required):

```bash
docker run -d --name nodeira-postgres \
  -e POSTGRES_DB=nodeira -e POSTGRES_PASSWORD=postgres \
  -p 5432:5432 postgres:17-alpine
cp apps/api/.env.example apps/api/.env
cd apps/api && pnpm exec prisma migrate dev    # apply migrations to the dev DB
```

**Schema changes use migrations** — `schema.prisma` is not applied directly. After editing it, run
`cd apps/api && pnpm exec prisma migrate dev --name <description>` to generate and apply a migration,
and commit the generated file under `apps/api/prisma/migrations/`. The server runs `prisma migrate deploy`
on startup (see `prisma.service.ts`), so committed migrations apply automatically in every environment.
Do **not** use `prisma db push` (it drifts the DB from the migration history).

## Architecture

### Sync (the core design)

Yjs CRDTs power offline-first sync. Every note is a Yjs document:

```
Browser
  ├── TipTap editor  (display layer)
  ├── Y.Doc          (in-memory CRDT — source of truth)
  ├── y-indexeddb    (offline persistence, survives refresh)
  └── y-websocket    (online sync → proxied through Vite → NestJS /sync/<noteId>)
          ↓
NestJS server (:3001)
  └── SyncGateway → HocuspocusService
      ├── onLoadDocument: reads yjsState (base64) from PostgreSQL, applies to Y.Doc
      └── onStoreDocument: encodes Y.Doc state, writes base64 back to PostgreSQL
          ↓
PostgreSQL  (notes.yjs_state TEXT column)
```

Offline-first works because y-indexeddb restores the full document from IndexedDB before the WebSocket connects. On reconnect, Yjs automatically merges changes from both sides — no conflict resolution code needed.

### NestJS server structure

- `DatabaseModule` — global Prisma provider (`PrismaService`), injected via DI
- `NotesModule` — REST CRUD for note metadata (`GET/POST/DELETE /notes`)
- `SyncModule` — WebSocket gateway + HocuspocusService for Yjs sync

The WS adapter is set to raw WebSocket (`WsAdapter` from `@nestjs/platform-ws`) — NOT Socket.IO. Hocuspocus uses the y-websocket protocol which requires raw WS framing.

`reflect-metadata` must be the **first import** in `apps/api/src/main.ts`. Server uses `module: "CommonJS"` with `verbatimModuleSyntax: false` because NestJS decorators require CommonJS + emitDecoratorMetadata.

### Web app structure

- `src/providers/YjsProvider.ts` — module-level `Map<noteId, YjsContext>` cache. Not React state — Yjs docs must survive re-renders and route transitions without reconnecting.
- `src/store/atoms.ts` — Jotai atoms: `notesListAtom`, `activeNoteIdAtom`
- `src/routes/` — TanStack Router file-based routes. `routeTree.gen.ts` is auto-generated by `@tanstack/router-plugin` on every `pnpm dev` / `vite build` — do not edit it.
- Vite proxies `/api` → `http://localhost:3001` (REST) and `/sync` → `ws://localhost:3001` (WebSocket).

TipTap's `StarterKit` must always be configured with `{ history: false }` when using Yjs — Yjs owns undo/redo.

Mantine v9 requires explicit CSS imports in `main.tsx`:

```typescript
import "@mantine/core/styles.css";
import "@mantine/notifications/styles.css";
```

## React Conventions

Avoid `useEffect` for derived state or event-driven logic (see `no-useeffect.md`):

- **Don't use Effects** to transform data for rendering or to handle user events
- **Do use Effects** to synchronize with external systems (non-React widgets, WebSockets, browser APIs)

Prefer Jotai atoms for shared state. The Yjs provider is module-level state (not atoms) because Yjs connection lifecycle must be decoupled from React's render cycle.

## UI

Use Mantine v9 components. The `llms.txt` file in the repo root contains Mantine v9 API documentation for LLM reference.

When using Mantine's polymorphic components (e.g., `NavLink`) with TanStack Router's `Link`, wrap `Link` as the outer element rather than passing it via the `component` prop — TanStack Router's typed params don't propagate through Mantine's polymorphism.
